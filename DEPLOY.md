# Free-tier deployment runbook

Everything here runs on **$0 fixed cost**:

| Piece | Service | Free limits |
|---|---|---|
| Database | Neon | 0.5 GB, sleeps after ~5 min idle |
| API + sockets | Render | 750 hrs/mo, sleeps after 15 min idle |
| 4 frontends | Vercel Hobby | static hosting (see ToS note) |
| Meetings | Jitsi `meet.jit.si` | unlimited, no account |
| Email | Gmail SMTP | 500 recipients/day |
| WhatsApp | Twilio Sandbox | allowlisted numbers only |
| Payments | Razorpay test mode | unlimited test transactions |
| Recording | — | not free (see note at the end) |

```
Browser ──► https://student-xxx.vercel.app
                 │  /api/*  and  /socket.io/*  rewritten by vercel.json
                 ▼
            https://edtech-api.onrender.com   (Express + Socket.IO)
                 │
                 ▼
            Neon Postgres (pooled)
```

The `/api` rewrite is essential. Session cookies are `sameSite: 'strict'`, so a
browser talking to a different site would silently drop them and every page
would show "invalid session".

## 0. What to collect before starting

Create these accounts first (all free, no card except Razorpay KYC later):

- [ ] **Neon** — project created, both connection strings copied
- [ ] **Render** — signed in with GitHub, repo access granted
- [ ] **Vercel** — signed in with GitHub
- [ ] **Gmail** — 2-Step Verification on, an **App Password** generated
- [ ] **Twilio** — Account SID + Auth Token, your phone joined to the WhatsApp sandbox
- [ ] **Razorpay** — test `key_id` + `key_secret`
- [ ] A strong admin password (12+ characters)

Put secrets in one file outside the repo, for example:

```bash
mkdir -p /tmp/opencode && chmod 700 /tmp/opencode
$EDITOR /tmp/opencode/deploy.env   # then: chmod 600 /tmp/opencode/deploy.env
```

Never commit that file and never paste it into a public issue.

## 1. Neon (database)

1. https://neon.com → sign up with GitHub → **Create project**
2. Name `edtech`, region **AWS ap-southeast-1 (Singapore)**, Postgres 17
3. **Connect** panel → copy **two** strings:
   - **Pooled** (host contains `-pooler`) → for the running API
   - **Direct/unpooled** → for migrations only

Both end with `?sslmode=require`.

## 2. Create the schema (run from your laptop)

```bash
cd backend
DATABASE_URL="<DIRECT string>" PGSSLMODE=require npm run db:migrate
```

Expected: `Database schema is up to date.` (24 tables)

Then seed once, with your real admin account:

```bash
DATABASE_URL="<DIRECT string>" PGSSLMODE=require \
  BOOTSTRAP_ADMIN_NAME="Platform Administrator" \
  BOOTSTRAP_ADMIN_EMAIL="you@example.com" \
  BOOTSTRAP_ADMIN_PASSWORD="at-least-12-characters" \
  npm run db:seed
```

This also creates `student@edtech.test / Student@12345` and
`teacher1@edtech.test / Teach@123456`. Delete them before sharing the URL:

```sql
DELETE FROM users WHERE email IN ('student@edtech.test','teacher1@edtech.test','teacher2@edtech.test');
```

## 3. Render (API)

1. https://render.com → **New** → **Blueprint** → pick this repo
2. It reads `render.yaml` and creates **`edtech-api`** — keep that exact name,
   the Vercel rewrites point at `https://edtech-api.onrender.com`
3. Fill in the `sync: false` variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon **pooled** string |
| `BOOTSTRAP_ADMIN_*` | same values you seeded with |
| `SMTP_*` | see step 5 |
| `TWILIO_*` | see step 6 |
| `RAZORPAY_KEY_ID` / `_SECRET` | your test keys |
| `ADMIN/TEACHER/STUDENT/HOME_ORIGIN` | fill after step 4 |

`JWT_SECRET` and `FIELD_ENCRYPTION_KEY` are generated by Render. **Never
regenerate them** — `FIELD_ENCRYPTION_KEY` decrypts stored MFA secrets.

Verify:

```bash
curl https://edtech-api.onrender.com/api/health
# {"status":"ok","database":"connected"}
```

## 4. Vercel (four frontends)

Import the **same repo four times**:

| Project | Root Directory | Framework | Build | Output |
|---|---|---|---|---|
| student | `student` | Vite | `npm run build` | `dist` |
| admin | `admin` | Vite | `npm run build` | `dist` |
| teacher | `teacher` | Vite | `npm run build` | `dist` |
| home | `home` | Vite | `npm run build` | `dist` |

Each folder already has `vercel.json` with the `/api`, `/socket.io` and SPA
rewrites. If you rename the Render service, edit the `destination` in all four.

### Build-time variables

Set these, then **redeploy** (Vite bakes them in at build time):

- **admin**: `VITE_STUDENT_PORTAL_URL`, `VITE_TEACHER_PORTAL_URL`
- **teacher**: `VITE_ADMIN_PORTAL_URL`, `VITE_STUDENT_PORTAL_URL`
- **home**: `VITE_STUDENT_PORTAL_URL`, `VITE_TEACHER_PORTAL_URL`

Do **not** set `VITE_API_URL` — the apps use relative `/api` on purpose.

Then go back to Render and set the four `*_ORIGIN` variables to the Vercel
production domains, and redeploy the API.

## 5. Gmail SMTP (free email)

1. Google Account → Security → enable **2-Step Verification**
2. Security → **App passwords** → app "Mail" → copy the 16-character value
3. Set on Render:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=youraddress@gmail.com
SMTP_PASSWORD=<16-char app password>
SMTP_FROM=ELITE <youraddress@gmail.com>
```

Limits: 500 recipients/day, From must be that Gmail. When volume grows, switch
to a free transactional provider (Brevo ~300/day, Resend ~100/day) — same SMTP
variables, different host.

## 6. WhatsApp (free sandbox)

1. https://console.twilio.com → Messaging → **Try it out → Send a WhatsApp message**
2. From your phone, send the shown `join <code>` to **+1 415 523 8886**
3. Set on Render:

```
TWILIO_ACCOUNT_SID=AC...
TWILIO_AUTH_TOKEN=...
TWILIO_WHATSAPP_FROM=whatsapp:+14155238886
TWILIO_SANDBOX_MODE=true
TWILIO_TEST_RECIPIENTS=+91XXXXXXXXXX
```

Only numbers that joined the sandbox receive messages. This is fine for demos.
Production needs Meta business verification + an approved **utility template**,
and costs about **₹0.115 per message** in India after the first 1,000 free
service messages/month.

## 7. End-to-end test

1. Student registers → enrolls authenticator
2. Books a slot, teacher approves
3. Student pays with a Razorpay test card (`4111 1111 1111 1111`, any future date, any CVV)
4. Confirmation email + WhatsApp should contain a `https://meet.jit.si/...` link
5. Open the link in two tabs → both sides connect

## Troubleshooting

| Symptom | Cause |
|---|---|
| Logged in but every page 401s | `/api` rewrite missing or `*_ORIGIN` wrong |
| `Google Meet is not configured` | `MEETING_PROVIDER=google_meet` without OAuth keys; use `jitsi` |
| Emails never arrive | SMTP empty — check Render logs for `skipped` |
| WhatsApp silent | number not joined to sandbox / not in `TWILIO_TEST_RECIPIENTS` |
| First request takes 40 s | Render free tier woke from sleep (normal) |
| `relation "..." does not exist` | migration not run against this database |
| Upload/first login fails after redeploy | `FIELD_ENCRYPTION_KEY` changed |

## Notes / honest limits

- **Vercel Hobby is for non-commercial use.** A paid tutoring business is
  technically outside its terms; Pro is $20/mo. Fine while testing.
- **Render free sleeps**, which drops live chat sockets. Upgrade (~$7/mo) when
  real students depend on it.
- **Recording is not free.** Jitsi's public server cannot record. Cheapest
  options: Zoom Pro (~$14/mo, cloud recording), Workspace Business Standard
  (~$14/user/mo), or self-hosted Jitsi + Jibri (~$6/mo VPS).
- **Razorpay test mode** is free forever; live mode needs KYC and charges ~2% + GST.
