# Free-tier deployment runbook

## Live environment

| Piece | URL |
|---|---|
| API (Render) | https://edtech-api-bvir.onrender.com/api/health |
| Student portal | https://elite-ed-tech-student.vercel.app |
| Admin portal | https://elite-ed-tech-admin.vercel.app |
| Teacher portal | https://elite-ed-tech.vercel.app |
| Marketing home | https://elite-ed-tech-home.vercel.app |
| Database | Neon `ep-royal-king-biuzlwcn` (ap-southeast-1) |

All four Vercel projects build from `Elite955/EliteEdTech` → `main`, each with its
own Root Directory, and proxy `/api` + `/socket.io` to the Render service.

Everything here runs on **$0 fixed cost**:

| Piece | Service | Free limits |
|---|---|---|
| Database | Neon | 0.5 GB, sleeps after ~5 min idle |
| API + sockets | Render | 750 hrs/mo, sleeps after 15 min idle |
| 4 frontends | Vercel Hobby | static hosting (see ToS note) |
| Meetings | Jitsi `meet.jit.si` | unlimited, no account |
| Email | Gmail SMTP | 500 recipients/day |
| Payments | Razorpay test mode | unlimited test transactions |
| Recording | — | not free (see note at the end) |

```
Browser ──► https://student-xxx.vercel.app
                 │  /api/*  and  /socket.io/*  rewritten by vercel.json
                 ▼
            https://edtech-api-bvir.onrender.com   (Express + Socket.IO)
                 │
                 ▼
            Neon Postgres (pooled)
```

The `/api` rewrite is essential. Session cookies are `sameSite: 'strict'`, so a
browser talking to a different site would silently drop them and every page
would show "invalid session".

## 1. Neon (database)

1. https://neon.com → sign up with GitHub → **Create project**
2. Name `edtech`, region **AWS ap-southeast-1 (Singapore)**, Postgres 17
3. **Connect** panel → copy **two** strings:
   - **Pooled** (host contains `-pooler`) → for the running API
   - **Direct/unpooled** → for migrations only

Both end with `?sslmode=require`.

## 2. Create the schema (run from your laptop)

```bash
cd backend
DATABASE_URL="<DIRECT string>" PGSSLMODE=require npm run db:migrate
```

Expected: `Database schema is up to date.` (24 tables)

Then seed once, with your real admin account:

```bash
DATABASE_URL="<DIRECT string>" PGSSLMODE=require \
  BOOTSTRAP_ADMIN_NAME="Platform Administrator" \
  BOOTSTRAP_ADMIN_EMAIL="you@example.com" \
  BOOTSTRAP_ADMIN_PASSWORD="at-least-12-characters" \
  npm run db:seed
```

This also creates `student@edtech.test / Student@12345` and
`teacher1@edtech.test / Teach@123456`. Delete them before sharing the URL:

```sql
DELETE FROM users WHERE email IN ('student@edtech.test','teacher1@edtech.test','teacher2@edtech.test');
```

## 3. Render (API)

1. https://render.com → **New** → **Blueprint** → pick this repo
2. It reads `render.yaml` and creates **`edtech-api`** — keep that exact name,
   the Vercel rewrites point at `https://edtech-api-bvir.onrender.com`
3. Fill in the `sync: false` variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Neon **pooled** string |
| `BOOTSTRAP_ADMIN_*` | same values you seeded with |
| `SMTP_*` | see step 5 |
| `RAZORPAY_KEY_ID` / `_SECRET` | your test keys |
| `RAZORPAY_WEBHOOK_SECRET` | see step 6 |
| `ADMIN/TEACHER/STUDENT/HOME_ORIGIN` | fill after step 4 |

`JWT_SECRET` and `FIELD_ENCRYPTION_KEY` are generated by Render. **Never
regenerate them** — `FIELD_ENCRYPTION_KEY` decrypts stored MFA secrets.

Verify:

```bash
curl https://edtech-api-bvir.onrender.com/api/health
# {"status":"ok","database":"connected"}
```

## 4. Vercel (four frontends)

Import the **same repo four times**:

| Project | Root Directory | Framework | Build | Output |
|---|---|---|---|---|
| student | `student` | Vite | `npm run build` | `dist` |
| admin | `admin` | Vite | `npm run build` | `dist` |
| teacher | `teacher` | Vite | `npm run build` | `dist` |
| home | `home` | Vite | `npm run build` | `dist` |

Each folder already has `vercel.json` with the `/api`, `/socket.io` and SPA
rewrites. If you rename the Render service, edit the `destination` in all four.

### Build-time variables

Set these, then **redeploy** (Vite bakes them in at build time):

- **admin**: `VITE_STUDENT_PORTAL_URL`, `VITE_TEACHER_PORTAL_URL`
- **teacher**: `VITE_ADMIN_PORTAL_URL`, `VITE_STUDENT_PORTAL_URL`
- **home**: `VITE_STUDENT_PORTAL_URL`, `VITE_TEACHER_PORTAL_URL`

Do **not** set `VITE_API_URL` — the apps use relative `/api` on purpose.
You **must** set `VITE_SOCKET_URL=https://edtech-api-bvir.onrender.com` on
`student`, `admin` and `teacher`: WebSocket upgrades are not proxied by a
Vercel rewrite, so the socket connects to Render directly and authenticates with
a short-lived `/api/auth/socket-token` token.

Then go back to Render and set the four `*_ORIGIN` variables to the Vercel
production domains, and redeploy the API.

## 5. Gmail SMTP (free email)

1. Google Account → Security → enable **2-Step Verification**
2. Security → **App passwords** → app "Mail" → copy the 16-character value
3. Set on Render:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=youraddress@gmail.com
SMTP_PASSWORD=<16-char app password>
SMTP_FROM=ELITE <youraddress@gmail.com>
```

Limits: 500 recipients/day, From must be that Gmail. When volume grows, switch
to a free transactional provider (Brevo ~300/day, Resend ~100/day) — same SMTP
variables, different host.

## 6. Razorpay webhook + go-live

The webhook is what makes a payment survive a closed browser tab. After Razorpay
captures money it calls our API directly; the API marks the booking paid, creates
the Jitsi room, and sends the receipt email. Without it, a payment completed in
a tab that is then closed would leave the booking stuck as `approved`.

### 6a. Register the webhook (do this in test mode first)

1. Open https://dashboard.razorpay.com/app/webhooks
2. **Add Webhook**
3. URL: `https://edtech-api-bvir.onrender.com/api/payments/webhook`
4. Event: **`payment.captured`** only (do not enable all events)
5. Webhook secret: generate a long random string, e.g.

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

6. Save the secret somewhere safe — Razorpay shows it only once.

Then on **Render → edtech-api → Environment** set:

```
RAZORPAY_WEBHOOK_SECRET = <the exact same secret>
```

Save and let it redeploy. Check:

```
https://edtech-api-bvir.onrender.com/api/integrations/status
```

must show `"payments": { "webhook": true }`.

The handler verifies the `x-razorpay-signature` HMAC against the raw body and is
idempotent: a replayed webhook does not create a second class session. Verified
locally with a signed payload and a replay:

```
bad signature : 400 {"error":"Webhook signature verification failed."}
captured      : 200 {"received":true}
replay        : 200 {"received":true}
final state   : booking=paid, sessions=1, meeting=https://meet.jit.si/…,
                payment=succeeded, notifications=2
```

The Render free tier sleeps after 15 minutes, so the first webhook after idle may
take up to ~40 s. Razorpay retries failed deliveries automatically, and our
signature check plus idempotency make retries safe.

### 6b. Go live (only when the client is ready)

1. **Use the client's Razorpay account, not yours.** Money settles into their
   bank account and KYC uses their PAN/business documents.
2. Complete Razorpay KYC / account activation in that account.
   Live `rzp_live_…` keys appear once activated.
3. Create a separate live webhook in the **live** mode toggle of the Razorpay
   dashboard, with the same URL and event, and a **new** secret.
4. On Render, replace the four payment variables:

   ```
   RAZORPAY_KEY_ID        = rzp_live_…       (never rzp_test_…)
   RAZORPAY_KEY_SECRET    = <live secret>
   RAZORPAY_WEBHOOK_SECRET = <live webhook secret>
   RAZORPAY_TEST_MODE      = false
   ```

5. Save → Render redeploys → verify the status endpoint shows
   `"testMode": false, "webhook": true, "razorpay": true`.
6. Do one small real transaction and confirm end to end: booking becomes `paid`,
   a Jitsi link appears immediately, the receipt email arrives, and the admin
   Transactions page shows the live payment ID.
7. Refund that test transaction manually in the Razorpay dashboard. The admin
   refund button is intentionally disabled outside test mode.

Notes:
- The test card `4111 1111 1111 1111` stops working in live mode.
- Neither API key nor the webhook secret may be committed. If a key is pasted
  into chat or a ticket, rotate it in Razorpay immediately.
- Razorpay charges ~2% + GST per transaction; there is no free live tier.

## 6b. Teacher moderator (JaaS Dev, free)

Public `meet.jit.si` requires the first person in a room to log in with Google,
GitHub or Facebook before the conference starts. Anonymous embeds cannot be
promoted to moderator. To make the teacher an automatic moderator, use the free
**8x8 JaaS Dev** plan (25 monthly active users).

1. Sign up 👉 https://jaas.8x8.vc
2. In the JaaS Console, create an **API Key** and download its **private key**
   (RS256). Note the **App ID** (looks like `vpaas-magic-cookie-…`) and the
   **Key ID / kid**.
3. On Render set:

```
JAAS_APP_ID       = vpaas-magic-cookie-...
JAAS_API_KEY_ID   = <kid from the JaaS console>
JAAS_PRIVATE_KEY  = <PEM private key; literal \n is accepted>
```

4. Save → Render redeploys. The join dialog now loads
   `https://<APP_ID>.8x8.vc/external_api.js` and passes a short-lived JWT with
   `context.user.moderator = true` for teachers and `false` for students.
   The teacher joins as moderator and the class starts immediately.

If these variables are left empty, the app falls back to public Jitsi. In that
mode the teacher must open the room in a new tab, log in with Google/GitHub/
Facebook, and then students can join. Also note `meet.jit.si` now limits rooms
to 95 minutes. JaaS recording/streaming are paid add-ons.

## 7. End-to-end test

1. Student registers → enrolls authenticator
2. Books a slot, teacher approves
3. Student pays with a Razorpay test card (`4111 1111 1111 1111`, any future date, any CVV)
4. Confirmation email should contain a `https://meet.jit.si/...` link and the PDF receipt attached
5. Open the link in two tabs → both sides connect

### Teacher hourly rate

Teachers set the rate **when they publish an availability slot**, together with
the subject and time — not during registration. The rate can be any value from
**₹0 to ₹4,999 per hour**, enforced in the UI, API validation, and a database
CHECK constraint. The booking amount is computed on the server as
`hours × the rate on the chosen slot`, so the browser cannot change it.

On successful registration, every user receives a welcome email with a PDF
account summary (registration bill: ₹0) and step-by-step instructions.

A teacher who sets **₹0** on a slot offers free classes: the student skips
Razorpay entirely, the booking is confirmed immediately, and the Jitsi link and
receipt email are generated straight away. This is handled by
`/api/payments/order` returning `{ "free": true }`; there is no zero-amount
Razorpay order.

If Razorpay's webhook confirms a payment before the browser does, `/verify`
returns `{"status":"paid","alreadyConfirmed":true}` instead of an error.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Logged in but every page 401s | `/api` rewrite missing or `*_ORIGIN` wrong |
| `Google Meet is not configured` | `MEETING_PROVIDER=google_meet` without OAuth keys; use `jitsi` |
| Emails never arrive | SMTP empty — check Render logs for `skipped` |
| First request takes 40 s | Render free tier woke from sleep (normal) |
| `relation "..." does not exist` | migration not run against this database |
| Upload/first login fails after redeploy | `FIELD_ENCRYPTION_KEY` changed |

## Notes / honest limits

- **Vercel Hobby is for non-commercial use.** A paid tutoring business is
  technically outside its terms; Pro is $20/mo. Fine while testing.
- **Render free sleeps**, which drops live chat sockets. Upgrade (~$7/mo) when
  real students depend on it.
- **Recording is not free.** Jitsi's public server cannot record. Cheapest
  options: Zoom Pro (~$14/mo, cloud recording), Workspace Business Standard
  (~$14/user/mo), or self-hosted Jitsi + Jibri (~$6/mo VPS).
- **Razorpay test mode** is free forever; live mode needs KYC and charges ~2% + GST.
